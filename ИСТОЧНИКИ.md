## Две разные судьбы, не перепутать

**Каталоги в корне — канон переехал сюда.** Три исходных репозитория заархивированы на GitHub:
они read-only, в их README стоит указатель на эту сборку. Работать с этим кодом надо
здесь, обычными коммитами. Ничего доставать оттуда и никуда синхронизировать не нужно.

**`upstream/* — канон остался у Яндекса.`** Эти репозитории чужие, заархивировать их
нельзя, и Яндекс продолжает их развивать. Здесь лежит снимок на дату из таблицы. Он
устареет, и это нормально.

## Обновить снимок `upstream/`

Сабтри намеренно не используется: он тянет за собой remote'ы, разные дефолтные ветки
и `subtree pull`, который при неверной ветке молча тянет не то. Обновление — обычное
копирование, зато его видно целиком:

```bash
TMP=$(mktemp -d)
git clone --depth 1 https://github.com/yandex-cloud/mcp.git "$TMP/mcp"
rm -rf upstream/yandex-cloud-mcp
cp -r "$TMP/mcp" upstream/yandex-cloud-mcp
rm -rf upstream/yandex-cloud-mcp/.git
git -C "$TMP/mcp" rev-parse HEAD    # ← новый SHA, вписать в таблицу выше
rm -rf "$TMP"
```

То же самое для `yandex-search-mcp-server`, только URL другой и ветка `main`.

**После обновления обязательно вписать новый SHA в таблицу.** Таблица и есть смысл
этого файла: без неё через месяц нельзя сказать, какой версии Яндекса соответствует
лежащий здесь код, а `.git` внутри снимка мы не храним.

## Что было изменено относительно источников

Снимки `upstream/*` — без единой правки, ровно как у Яндекса. Apache 2.0 требует
отмечать изменения; изменений нет, отмечать нечего.

В `wordstat-sweep/scripts/wordstat_gate.py` добавлена одна строка —
`from __future__ import annotations`. Скрипт использует аннотации вида `Path | None`,
которые до питона 3.10 падают с `TypeError` ещё на этапе разбора файла. Строка снимает
это, ничего не меняя на 3.10+. Рядом добавлен `README.md`, которого в источнике не
было: соседний `SKILL.md` писался под конкретную машину и содержит абсолютные пути
`D:/Yahia/...`, для стороннего читателя это шум.
