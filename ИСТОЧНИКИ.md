## Три разные судьбы, не перепутать

**Каталоги, помеченные 🗄 — канон переехал сюда.** Исходные репозитории заархивированы
на GitHub: они read-only, в их README стоит указатель на эту сборку. Работать с этим
кодом надо здесь, обычными коммитами.

**Каталоги, помеченные ▲ и принадлежащие автору — пока живут в двух местах.** Источники
не заархивированы: часть из них опубликована в npm, и архивация закрыла бы им issues.
Пока это не решено, правку надо отдавать в оба места либо не делать здесь вовсе.

**`upstream/*` — канон остался у Яндекса.** Эти репозитории чужие, заархивировать их
нельзя, и Яндекс продолжает их развивать. Здесь снимок на дату из таблицы. Он
устареет, и это нормально.

## Обновить снимок

Сабтри намеренно не используется: он тянет за собой remote'ы, разные дефолтные ветки
и `subtree pull`, который при неверной ветке молча тянет не то. Обновление — обычное
копирование, зато его видно целиком:

```bash
TMP=$(mktemp -d)
git clone --depth 1 https://github.com/yandex-cloud/mcp.git "$TMP/mcp"
rm -rf upstream/yandex-cloud-mcp
cp -r "$TMP/mcp" upstream/yandex-cloud-mcp
rm -rf upstream/yandex-cloud-mcp/.git
git -C "$TMP/mcp" rev-parse HEAD    # ← новый SHA, вписать в таблицу выше
rm -rf "$TMP"
```

Для остальных то же самое, только URL другой. `--depth 1` без `-b` берёт дефолтную
ветку, указывать её отдельно не нужно.

**После обновления обязательно вписать новый SHA в таблицу.** Таблица и есть смысл
этого файла: без неё через месяц нельзя сказать, какой версии исходного кода
соответствует лежащий здесь снимок, а `.git` внутри снимков мы не храним.

## Почему YaGEO взят не с master

Снимок `skills/yageo` сделан с ветки `refactor/burn-2026-06-24`, а не с дефолтной
`master`. Причина: на момент архивации репозитория master отставал на три месяца.
Ветка — строгое надмножество: 27 новых файлов, тринадцать тестов против пяти, а
правки существующих файлов это распил монолитов на подмодули (`epos_scorer.py`
−560 строк, `json_ld_validator.py` −530, `yandex_crawler_check.py` −347 — содержимое
переехало в `_epos_*`, `_jsonld_*`, `_crawler_*`). Из master в ветке нет только
сегодняшних правок README с указателем на эту сборку.

Главное, чего не было в master: `scripts/mcp_server.py` — YaGEO обзавёлся
собственным MCP-сервером, — плюс `scripts/config.py`, `scripts/cache.py` и
вынесенная наружу конфигурация `yageo/epos_config.toml`.

Не перенесены два артефакта, отслеживавшихся в ветке по недосмотру: `.coverage`
(53 КБ) и `research/scripts/brave_sweep.py.bak-268ca6ed` (64 КБ). Итого 107 файлов
из 109.

## Мёртвые воркфлоу внутри снимков

У `mcp/yandex-direct-mcp` и `mcp/yandex-metrika-mcp` есть собственные
`.github/workflows/ci.yml` — они приехали вместе со снимками и **не работают**:
GitHub Actions читает воркфлоу только из корневого `.github/workflows/`. Файлы
оставлены как есть, чтобы снимки оставались точными. Реальная сборка всех пакетов —
в корневом `.github/workflows/ci.yml`.

## Что было изменено относительно источников

Снимки `upstream/*` — без единой правки, ровно как у Яндекса. Apache 2.0 требует
отмечать изменения; изменений нет, отмечать нечего.

Изменения в своих частях, все умышленные:

- **`skills/wordstat-sweep/scripts/wordstat_gate.py`** — добавлена строка
  `from __future__ import annotations`. Скрипт использует аннотации `Path | None` и
  `list[dict]`, которые до питона 3.10 роняют модуль при импорте с
  `TypeError: unsupported operand type(s) for |`. Строка снимает это, ничего не меняя
  на 3.10 и выше.
- **`skills/wordstat-sweep/README.md`** — новый, в источнике его не было. Соседний
  `SKILL.md` писался под конкретную машину и содержит абсолютные пути `D:/Yahia/...`.
  Для стороннего читателя это шум, полезное из него сведено в README.
- **`skills/wordstat-sweep/scripts/collect_semantics.py`** и
  **`skills/yageo-audit/scripts/yageo_gate.py`** — добавлены. Оба скилла документировали
  эти файлы как «оставшиеся на выключенном ПК»; на деле они существовали в других
  проектах и просто не доехали. `collect_semantics.py` содержит маппинг страниц под
  конкретный сайт и требует правки под свой проект.
- **`mcp/yandex-search-mcp`** — из монорепозитория `WWmcp` перенесены только девять
  файлов, отслеживаемых git. Сборочные артефакты (`dist/`, `node_modules/`, `.turbo/`)
  не переносились.
