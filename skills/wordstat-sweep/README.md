# wordstat-sweep

Скилл Claude Code поверх Yandex Wordstat API. Два режима на одном эндпоинте
`v2/wordstat/topRequests` — не путать между собой.

| Режим | Скрипт | Задача | Состояние |
|---|---|---|---|
| **Gate** | `scripts/wordstat_gate.py` | проверить, есть ли под нишу реальный поисковый спрос, ДО разработки | ✅ здесь, работает |
| **SEO-ядро** | `scripts/collect_semantics.py` | собрать семантическое ядро перед написанием контента | ✅ здесь, требует правки под свой проект |

## Зачем он вообще

Wordstat живёт в Yandex Search API — тот же ключ, тот же folder, что у
`../../upstream/yandex-search-mcp-server`. Но **ни в одном официальном MCP-сервере
Яндекса статистики запросов нет**: оба поисковых сервера отдают только веб-поиск.
Дыру закрывают две вещи из этой сборки: этот скилл и MCP-сервер
`../../mcp/yandex-search-mcp`.

## Метод

На нишу берётся 4–6 seed-фраз с покупательским намерением. Объём по seed — **максимум
в раскрытии `topRequests`**, а не count точной фразы: это защищает от ложного RED,
который дают склонения и порядок слов. Сумма top-3 seeds = `combined`, по нему вердикт:

| combined top-3 | Вердикт |
|---|---|
| ≥ 5000/мес | GO |
| 2000–4999 | MAYBE-PILOT |
| < 2000 | RED/PIVOT |

Три правила чтения вывода, без которых цифры врут:

1. **`combined` — верхняя граница.** Смотри `[top: ...]` по каждому seed: если объём
   набран одним широким информационным термином без покупательского намерения — это
   ложный GO. Перепроверяй флагом `--exact`.
2. **Вердикт — валидация спроса, а не решение.** Идти или не идти — за человеком.
3. **`API-FAIL` ≠ RED.** Это отказ инфраструктуры (403, квота), а не мёртвая ниша.

Wordstat показывает только нижнюю границу спроса — то, что люди уже ищут словами, — и слаб для B2B — там ищут через сарафан и
тендеры. После гейта триангулируй: крутит ли кто-то Яндекс.Директ по тем же seeds
(значит, за клик уже платят), есть ли решения с отзывами в отраслевых каталогах.

## Запуск

```bash
export YANDEX_SEARCH_API_KEY=...
export YANDEX_FOLDER_ID=...

python3 scripts/wordstat_gate.py --selftest          # офлайн, без API и квоты

python3 scripts/wordstat_gate.py \
  --name "Маркетплейсы: защита селлера" \
  --gate "обжалование штрафа wildberries,оспорить штраф озон,защита селлера маркетплейс"

python3 scripts/wordstat_gate.py --gate-file niches.txt --json out.json
```

Ключ и folder скрипт также подхватывает из `.env.local` walk-up от текущего каталога.

**Флаги:** `--exact` — консервативный объём вместо максимума · `--gate-file PATH` —
много ниш из файла · `--selftest` — офлайн-проверка порогов без API · `--json PATH` —
структурный дамп · `--no-cache` — обойти кэш · `--name` — имя ниши для `--gate`.

Кэш живёт 30 дней в `$(pwd)/.wordstat-cache/`, переопределяется `WORDSTAT_GATE_CACHE`.
Rate-limit Яндекса ~100 запросов/час; на 429 скрипт делает три попытки с паузами 6 и 18 секунд.
Gate дёшев: 4–6 вызовов на нишу, повторы из кэша бесплатны.

**Диагностика.** `NO YANDEX CREDS` — не заданы `YANDEX_SEARCH_API_KEY` и
`YANDEX_FOLDER_ID`. `API-FAIL` с HTTP 403 `Permission denied` — ключ протух, либо у
сервисному аккаунту не хватает роли `search-api.executor` в этом каталоге, либо на
платёжном аккаунте нет денег.

## `collect_semantics.py` — эталон и вмороженные копии

Лежащий здесь файл — **эталон**. Скилл не запускает его на месте: он копирует его
в `<project>/research/scripts/` и дальше спринт работает со своей копией. Это
сделано намеренно — завершённый спринт воспроизводится ровно тем скриптом, которым
собирался, и задним числом не переписывается.

⛔ **Обратная сторона: копия старого спринта устаревает вместе со спринтом.**
Копии, снятые **до 25.07.2026**, не содержат двух исправлений и при перезапуске
тихо деградируют сбор:

| Что | В старых копиях | В эталоне |
|---|---|---|
| `MAX_RELATED` | `20` — «API отдаёт ≤20» | `100` — лимит был свой, не API. Живая проверка: просишь 100 — отдаёт 100 |
| Ошибка `topRequests` | молча `return []` | ретрай 429/таймаут с паузами 30/90/240 с |

С 27.09.2026 эталон — версия из GosMax (она ушла вперёд, сюда не возвращалась):

| Что | До 27.09 | Сейчас |
|---|---|---|
| `MAX_RELATED` | `100` | `2000` — один вызов, квота считает вызовы, а не фразы |
| Квота 100 вызовов/ч | реактивный ретрай, сид сгорал | `_pace()` держит окно в 95/ч (`WORDSTAT_QUOTA_PER_HOUR`); 429 ждёт 10/15/20 мин |
| Повторные вызовы | каждый прогон заново | JSONL-кэш в `research/_raw_data/wordstat_cache/`, обрыв продолжается с места |
| Рекурсия | `--depth 2` без порога | снежный ком: `--depth N --min-expand V`, крупные первыми; `--no-saturation` — без стопа по насыщению |
| «Также ищут» | не читались | из того же ответа, без квоты; только фразы с токеном бренда (`MAX_TOKEN`) |
| Шум омонимов | раскрывался | `NOISE` не раскрывается (Pro Max, Max Payne) |
| 401/403 (пустой баланс) | молча `return []` | стоп с кодом 2, кэш цел |

`MAX_TOKEN`, `NOISE` и `map_target_page` зашиты под MAX/gosmax — под другой бренд правь их.
Тесты: `python -m pytest scripts/test_collect_semantics.py` (офлайн).
Цена: GetTop — 20 ₽ за 1 000 вызовов (тарифы Search API, 27.09.2026).

Первое режет ядро **в 5 раз**. Второе опаснее: упор в квоту freemium (~100
запросов/час) выглядел не как ошибка, а как пустая выдача — сид терялся, а ядро
выглядело собранным. Тихий отказ ровно того сорта, который ловит `verify_core`.

**Правило:** пересобираешь семантику в старом спринте — сперва перезалей туда этот
файл, не запускай лежащую там копию. Расхождение видно по размеру: эталон 33 126 Б (27.09.2026),
копии до 27.09 — 22 902 Б и меньше.
